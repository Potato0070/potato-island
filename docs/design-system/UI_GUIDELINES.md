# 土豆岛 UI 与交互规范

版本：1.0
建立日期：2026-10-14
适用范围：后续移动端页面设计、预览和实现；页面专属颜色与结构须先经用户确认。

## 设计原则

- 页面以白色为主底色，信息层级清楚，操作入口可辨认；用留白组织内容，不用装饰元素填满空处。
- 延续岛民图鉴的手绘彩铅和轻水粉气质，使用低饱和的岛屿自然色；商品图和真实数据优先于装饰。
- 页面先做预览，用户确认后再修改产品代码。只把获准的页面视觉应用到对应页面，不推断为全站换肤。
- 每个控件说明一个功能；同一行里主分类比排序筛选更醒目，说明信息比操作按钮更轻。
- 预览生成的示例数据不得作为真实商品名、价格、成交数或库存写入产品。

## 字体层级

尺寸采用 React Native 逻辑像素（sp）。中文页面优先使用系统中文字体，不为单个页面引入新字体文件。

| 角色 | 字号 / 行高 | 字重 | 用途 |
|---|---:|---|---|
| 页面标题 | 22 / 28 | 700–800 | 顶部居中页面名，如“交易集市” |
| 区块标题 | 18 / 24 | 700 | 页面内主要内容分组 |
| 卡片标题 | 15 / 20 | 600–700 | 藏品或内容名称 |
| 正文与主要控件 | 14 / 20 | 400–600 | 搜索提示、分类名称、说明 |
| 价格与关键数值 | 18 / 24 | 700 | 价格、余额等主要数字；与币种或单位同组 |
| 次级筛选 | 12 / 16 | 500–600 | “最热、最新、价格排序、关注”等轻量选项 |
| 辅助信息 | 11 / 14 | 400–500 | 在售量、时间、状态和底栏标签 |

11 sp 是普通界面文字的最小值。只有密集的非核心辅助信息可使用 10 sp，并须验证手机实机可读性。一个页面最多使用四个常规字号层级，特殊数值可以独立突出。

## 间距与布局

- 间距使用 4 的倍数：4、8、12、16、20、24。避免页面里出现无意义的任意间距值。
- 手机页面左右内容边距通常为 16；内容区块垂直间距通常为 16 或 24。
- 双列藏品网格使用等宽列和 12 间距；藏品图固定 1:1，图片不拉伸。横向分类可滚动，不压缩文字。
- 次级页面标题居中显示页面名称，不重复放置品牌 Logo 与“土豆岛”字样。
- 底部内容为导航栏与安全区留出空间，列表末项不能被导航栏遮挡。

## 控件规格

| 控件 | 视觉规格 | 交互要求 |
|---|---|---|
| 搜索框 | 高 44–46，圆角 12–14，白或暖白底，暖浅灰描边 | 提示文案必须和实际搜索字段一致；保留键盘搜索行为 |
| 主分类 chip | 最小高 40，水平内边距 16 左右，圆角 12–14 | 选中态清楚；分类来源和顺序沿用后台动态数据 |
| 次级排序 | 高 32–36，字号 12；当前项使用浅雾霾蓝状态 | 视觉上弱于分类；保持可点击区域至少 40（可用 hitSlop 扩展） |
| 结果计数 | 字号 12、辅助色，显示在排序行左侧 | 按当前分类、搜索和关注结果动态更新；例如“共 128 件”仅为预览值 |
| 内容卡片 | 圆角 14–16，细描边，极轻阴影 | 点击区域和独立操作（如爱心）分开；状态可由颜色和文案共同表达 |
| 退市标记 | 陶土红底、浅色字、明显尺寸，可轻微倾斜 | 不能遮盖主体过多；仍需能看出藏品原图 |
| 底部导航 | 暖白半透明液态玻璃，柔和模糊、细边和轻阴影 | 五项固定顺序：首页、集市、旨意、消息、金库；透镜跟随按压与滑动 |

## 导航插图资源验收

- 每个运行时资源文件只包含一个完整主体，禁止从横向拼图直接切出带相邻图案的切片。
- PNG 必须含透明通道；图案在四边保留约 10% 的透明安全留白，画布边缘不能出现可见像素。
- 同一组图标统一光学尺寸与中心位置；缩放到实际 36 逻辑像素后检查，不能只验收大图。
- 同时在白色、暖灰色与深色检查底上验收透明边缘，并检查静止、按压放大和滑动过程。
- 源图归档到 E 盘资源库，仓库保留打包所需的轻量 PNG。2026-10-15 清理后的旨意、消息、金库图标位于 `assets/navigation/set-c-clean/`。

## 交易集市基线

- 顶部仅显示居中的“交易集市”。
- 搜索框位于标题下；其后为“全部藏品”与后台动态分类，保持后台原有名称和顺序。
- 排序项为“最热、最新、价格排序、关注”，靠右排列；左侧显示当前筛选结果数。
- “最热”继续按现有近 30 天成交规则排序；爱心关注继续使用本地偏好；筛选与排序不改交易记录。
- 商品卡片保持正方形图片；退市状态使用醒目的陶土红标；卡片数据取现有后端字段。
- 页面不添加预览稿没有对应业务的数据或额外筛选流程。

## 预览与实施流程

1. 先根据用户确认的要求做页面预览，检查移动端首屏、长内容、动态分类、空态和底部安全区。
2. 用户确认后实施；只改当前获准页面、已确认的共享导航或规范文件。
3. 实施后运行目标文件 lint、类型检查（如有既有错误需注明）、构建或导出检查，并记录结果。
4. 新页面使用本规范作为字号和布局基准，但颜色、模块和交互仍须各自先预览确认。
