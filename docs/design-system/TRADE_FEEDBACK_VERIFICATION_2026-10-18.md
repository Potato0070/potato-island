# 交易确认与保存反馈修复记录

日期：2026-10-18。

## 本轮范围

现货列表 → 购买确认 → 现有 execute_trade RPC → 成功刷新或失败留在确认框；旧版发布寄售 → 确认 → 带持有人和状态条件的单行更新 → 核对更新结果；个人资料 → 保存 → 核对返回记录 → 成功或保留输入。

复用已确认的海边卡册纸框和按钮素材，不增加新图片。确认框最大宽度 420，窄屏可换行排列按钮，内容可滚动。提交期间取消和确认均禁用，并以 ref 锁阻止同一页面重复请求。

## 修改

- 现货购买移除 Web 端旧 Alert 确认方式，显示藏品名称、编号和土豆币金额。未登录、自购会在 RPC 前拦截。RPC 成功后更新列表；查询失败明确提示重试，不显示为没有现货。
- 寄售更新增加 owner_id 和 idle 条件，并要求返回被更新的记录。零行更新、数据库报错都不会显示成功。失败保留价格和确认框。金额仅接受有限正数、最多两位小数；该页面币种统一为土豆币，取消输入自动聚焦并复用 Web 输入框重置样式。
- 资料保存检查认证、数据库错误及返回记录，失败保留昵称和头像；仅返回写入结果后显示成功。保存期间锁定编辑、保存和退出操作。退出失败也会明确反馈。

## 隔离验证证据

静态导出运行在 127.0.0.1:8189，构建的 Supabase 地址仅在测试服务器返回的 JS 中替换为本地假接口。未执行真实购买、寄售、资产转移或资料修改。假接口不转发任何请求到数据库，日志不记录凭据和请求正文。

| 场景 | 观察结果 |
| --- | --- |
| 未登录确认购买 | 显示登录提示，不调用交易 RPC |
| 取消购买 | 确认框关闭，cancel 场景写请求数为 0 |
| 双击购买确认，接口延迟 | 仅 1 次 execute_trade POST；提交中两按钮禁用 |
| 模拟购买成功 | 显示收入金库反馈，刷新后已售藏品消失 |
| 模拟购买失败 | 确认摘要仍在，显示失败提示，没有成功提示 |
| 保存资料报错 | 输入内容仍在，显示失败提示 |
| 保存返回零行 | 不显示成功，输入仍在 |
| 双击保存，接口延迟 | 仅 1 次 profiles PATCH，输入在提交中锁定 |
| 模拟资料保存成功 | 返回昵称显示在输入框，停留当前页面 |
| 寄售返回错误或零行 | 价格仍为 6，确认框显示错误，不显示上架成功 |
| 双击寄售确认 | publish-success 场景仅 1 次 nfts PATCH，返回记录后显示上架成功 |
| 非法金额 1.2.3 | 不进入确认流程，不提交更新 |
| 320px 窄屏 | 页面 scrollWidth 与 clientWidth 均为 320；纸框边界 x=16..304，无横向溢出，按钮自动分行 |

## 尚未完成的资金流程

竞价撮合、发布求购/竞价、撤回求购退款和加价仍存在客户端分次更新余额、订单或藏品的逻辑。前端锁无法保证跨请求事务一致性，也不能阻止多设备并发。

需要只读核对实际数据库表、权限和交易函数，再将这些操作放入数据库事务并验证失败回滚、并发和重放处理。当前未取得数据库函数定义，本轮没有新增未经部署的 RPC，没有迁移数据库，也没有用客户端补偿写入冒充事务。这些路径不能据本轮测试标为资金流程已修复。
