## 文件与范围

- `masters/`：20 件 PNG 原图，约 36.10 MB，存档用。
- `runtime/`：20 件透明 WebP，约 4.37 MB，后续页面优先使用。格式导出保持原图尺寸与透明通道，不重绘、不裁边、不强制变形。
- `generation-manifest.json`：每件完整提示词和生成来源。统一参考已确认的 A 素材板；三种按钮颜色以蓝色母版为编辑参考。
- `asset-manifest.json`：文件路径、真实宽高、字节数和初步文字安全区，坐标基于完整图片画布，使用 0–1 比例。
- `qa.json`：原图 alpha 范围、八处边缘采样和主要可见区域范围。包含透明留白的数据，不能把整张画布宽高误当成可见边框范围。

## 后续接入规则

1. 底图不包含业务文字。确认、购买、竞价等按钮共用语义底图，文案保持独立可访问文本；状态不能只靠颜色区分。
2. 面板不烘焙关闭按钮、拖动柄、标题或提交按钮；它们独立布局，点击区域至少 44 × 44。触屏主按钮点击高度至少 48。
3. `contentSafeArea` 是保守的初步建议，需要用真实文字在 320 / 375 / 430px 页面逐项核对。它不是已经验证过的全平台切片参数。
4. 编号完整显示，不能用省略号截断身份编号。竖签不够宽时改为横向编号展示，不能为了贴底牌把字号无限缩小。
5. 原图存在透明边距，而且不同素材的边距不同。接入时先参考 `bboxAlpha32` 核定可见区域，再制定九宫格切片参数。禁止直接把全部图片当作同尺寸背景拉伸、禁止一套不分素材的固定 padding。
6. 九宫格只允许延展稳定中心区域，四角与蓝色纸层保持比例；面板随内容长高，内容在安全区内独立滚动。正文不能定位到贴图外。
7. 彩色按钮中心纹理有明暗变化。初步抽样中深棕 `#21180F` 在蓝色底上的低分位对比度约 4.41:1、红色底约 3.48:1；小号普通文字不能据此宣称达标。优先使用较大粗体，并对最终字号和底图区域重新检查对比度。
8. 按下态可做轻微缩放/明暗反馈；提交中保留按钮尺寸、显示加载与明确文案并禁用重复提交。禁用不能只降低对比度而不提供原因。键盘焦点仍需清晰可见，采用平台一致的焦点样式。
9. 网页按页面需要引用 WebP，小控件可缓存。不要预加载整套；不要让页面读取存档 PNG；不要将素材总览拼图用于生产背景。
10. 已完成通用组件与购买、寄售、求购、竞价、加价、撤单页面的首批接入。独立预览中的成功、失败、材料不足仍是本地演示；原生键盘、真实资金处理和全平台接入尚未完成。详细范围参见应用接入验收文档。

## 组件预览

`components.html`、`components.css`、`components.js` 是独立的可点击预览，数据保存在当前页面内，不调用数据库或交易接口。它展示了四类按钮、加载/禁用/按下状态、暖棕输入焦点、金额错误、分类标签、搜索、编号/获取时间排序抽屉、确认/结果弹窗与材料选择抽屉。

`component-assets.js` 的布局数据来自真实 alpha 边界并保留 12 源像素的安全余量。预览用 SVG 视口显示原有 WebP 的九个区域，保留原始图像和四角比例，再延展中心。SVG 只是位图的布局容器，没有重画边框或替换素材。

基础尺寸：主按钮至少 56px 高，小控件点击区 48 × 48，输入字号 16px。文案最长时允许换行长高；加载态采用较短的“提交中”避免小按钮跳高。320px 确认框按钮纵向排列；抽屉内容独立滚动、底部确认保留在固定区域。部分选择有半选横线，所有勾选状态仍由原生复选框提供可访问语义。

[预览验证记录](./COMPONENT_PREVIEW_VERIFICATION.md) 包含检查结果及后续限制。

## 再导出

运行 `node export-web.cjs <sharp模块路径>`。脚本只做 WebP 格式导出，保留画布、alpha 和原图。`node create-gallery.cjs` 重建无外部网络依赖的总览页。`node create-component-data.cjs` 从现有清单生成组件布局数据。原图可追溯，替换资产时另起版本，不覆盖已确认的历史文件。
